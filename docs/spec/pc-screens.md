- ステータス: **検討中**。まだ要件に入れていない。着手するときに FR として
  [要件](requirements.md) へ移す。
- **FR-9「作り込まない」と正面から衝突する**。ここにある項目はどれも、要件の改訂に

  （`npm run spec:coverage`）。
- スマホ側は [スマホ画面設計](mobile-screens.md) が持つ。768px 未満は `AppLayout` を

## 1. 要望

使っていて出た要望。優先度は付けていない。

| ID | 要望 | 規模 |
| --- | --- | --- |
| P-01 | 本文を画面幅いっぱいに使う | 対応済み |
| P-02 | 会話に「次へ / 前へ」を付ける | 大 |
| P-03 | 一覧と本文を分割ビューにする（既定） | 大 |
| P-04 | 本文を全画面で開くボタン。設定で既定を選べる | 中 |

### P-01 本文の幅 — 対応済み

スレッド表示だけ `max-w-[1000px] mx-auto` で中央寄せだった。一覧は元から幅の指定が
無く全幅なので、本文もそれに揃えた（`src/ui/routes/ThreadDetail.tsx`）。

### P-02 次へ / 前へ

会話を開いたまま隣のメールへ移りたい。今は一度一覧へ戻るしかない。

**見た目より大きい。** ボタンを置くだけでは済まず、前後が何かを知る手段から要る:

- 一覧の状態は `Inbox.tsx` のローカル `useState`。画面遷移で破棄される。
- ストアもグローバル context も無い（あるのは `auth.tsx` の認証情報だけ）。
- URL で本文へ渡しているのは `view=trash` のみ。一覧のフィルタすら引き継いでいない。

つまり「一覧の順序を保つ層」の新設が前提になる。[スマホ画面設計](mobile-screens.md)
3 章の「通知から開いた会話を閉じると、一覧の位置を保つ」も同じ層を要求しているので、
まとめて設計したほうがよい。

### P-03 分割ビュー

クリックしたら右に本文が出る形（Yahoo メール式）を既定にしたい。

今は `/` と `/threads/:id` が排他のルートで、`AppLayout` の単一 `<Outlet />` を
入れ替える**画面遷移型**。分割ペインの下地は無い（リサイズ可能なペインの実装も、
その手の依存も無い）。

ただし `AppLayout` は既に flex なので、2 カラム化の改造自体は素直に入る見込み。
P-02 の「一覧の状態を保つ層」があれば、そのまま流用できる。

**未決**: 分割の向き（左右か上下か）。今の一覧は 1 行が横に長いので、左右に割ると
一覧側が窮屈になる可能性がある。実物で確かめてから決める。

### P-04 全画面ボタンと既定の設定

P-03 を入れるなら、本文だけを広く見たい場面のために全画面の導線も要る。
設定でどちらを既定にするか選べるとなおよい。

**設定の置き場**: 今の表示設定は localStorage にある（テーマが `src/ui/lib/theme.ts`、
サイドバーの開閉が `AppLayout.tsx`）。どちらも Settings 画面には出ていない。
新しい表示設定もこれに倣うのが自然で、API・契約・マイグレーションを触らずに済む。

ただし FR-9 は「設定項目は最小限」と明記している。増やすなら、そこの合意が要る。

## 2. 関連して気付いたこと

要望ではないが、見ていて気付いたもの。

- 一覧のチェックボックス（`Inbox.tsx`）は**見た目だけ**で、選択状態を持っていない。
  `onClick` は `preventDefault` / `stopPropagation` のみ。まとめて既読・削除のような
  操作を入れるなら、ここから。なお [スマホ画面設計](mobile-screens.md) の M-01 は
  「PC のチェックボックスは出さない」としている。
- 会話は全通を展開したまま（`ThreadDetail.tsx`）。スマホ側の M-03 は
  「最後の 1 通以外は畳む」としており、PC も同じにするかは未決。
- [architecture.md](architecture.md) の所有権表は `src/ui/routes/mail/` と書いているが、
  実体は `src/ui/routes/` 直下に平置き。`mail/` は無い。
