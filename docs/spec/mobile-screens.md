# スマホ画面設計（検討中）

- ステータス: **検討中**。方式とデータは [PWA とプッシュ通知](pwa-notifications.md)。
- 見た目のモックは画面設計キャンバス（URL は下の「モック」）。この文書が項目・状態・文言の正で、
  キャンバスは見た目の正。食い違ったらこの文書を直してからキャンバスを合わせる。

## 1. 方針

- **既存のトークンをそのまま使う**（`src/ui/styles.css`）。色・角丸 16px の `card`・丸いボタン・
  既読行の沈ませ方は PC と同じ。スマホ専用の色を作らない。
- 768px 未満でスマホ配置に切り替える。PC 用の画面を別に作らず、`AppLayout` を出し分ける。
- 押せるものは 44px 以上。一覧の行は 72px。
- **キャッチオールの受け皿には必ず「キャッチオール」のラベルを付ける**。メールボックス名が出るところすべて
  （切り替え・メニュー・一覧の行・会話・通知設定・通知欄・通知そのもの）。形は管理画面の `Badge` の
  yellow と同じ（薄い面に `--warning` の文字）。キャッチオール宛のメールには、本来の宛先も一緒に出す。
- 画面下の安全領域（`env(safe-area-inset-bottom)`）を避ける。`viewport-fit=cover`。
- 設定は **段階的開示**。トップはプリセットとスイッチだけで済み、細かい設定は 1 段奥に置く。
  奥の画面では、今の設定が何を意味するかを 1 行の要約で必ず見せる。

## 3. メール

### M-01 受信箱

- 上部: メニューボタン / メールボックス切り替え（色の丸 + アドレス + 未読数）/ ベル（通知欄。未確認があれば点）/
  アカウントの丸。
  その下に検索の入力欄（押すと `/search`）。
- 行: 差出人（未読は太字）/ 時刻 / 件名 / 本文の冒頭 / スター。横断表示のときは差出人の下に
  メールボックスの色とアドレス（FR-14）。PC のチェックボックスは出さない。
  キャッチオール宛の行は、アドレスの横に「キャッチオール」と「宛先 recruit@…」を出す。
- 右下に「作成」ボタン。スクロールで下へ動いている間は文字を畳んでアイコンだけにする。
- 下に引っぱって再読み込み。
- 通知から開いた会話を閉じると、ここに戻る（一覧の位置を保つ）。

### M-02 メニュー

PC のサイドバーと同じ項目: 受信箱 / スター付き / 送信済み / ゴミ箱 / 設定 / 管理（owner のみ）。
左からのドロワー。背景を押すと閉じる。

### M-03 会話

- 上部: 戻る / 件名（2 行まで）/ スター / ︙。
- ︙ の中: 「この会話の通知…」（M-04）/ ゴミ箱へ / 未読にする。
- メッセージは縦に並べ、最後の 1 通以外は畳む。
- 下に「返信」「全員に返信」を固定。

### M-04 会話の通知（シート）

- 選択肢 3 つ: **いつもどおり**（メールボックスの設定に従う）/ **返信を毎回通知**（フォロー）/
  **この会話は通知しない**（ミュート）。
- いつもどおりのとき、今の設定だとどうなるかを 1 行で出す（例: 「新しい会話だけ通知する設定のため、
  この会話の返信は通知されません」）。

## 4. ホーム画面に追加

### P-01 追加の案内（バナー）

- 出す条件: スマホ幅 / 追加していない（`display-mode: standalone` でない）/ 3 回目以降の訪問 /
  30 日以内に閉じていない。
- 受信箱の一覧の上に 1 枚。「ホーム画面に追加すると、新着をプッシュ通知で受け取れます」＋
  「追加する」「今はしない」。
- Android / PC は「追加する」でブラウザのインストールを呼ぶ。iOS は P-02 を開く。

### P-02 追加の手順（iOS シート）

- 3 手順を絵で示す（iOS 26 の手順）:
  ① 「…」を押して「共有」を選ぶ（共有ボタンが見えていればそれを押す）
  ② 「ホーム画面に追加」を選ぶ（見当たらなければ一覧を下へ）
  ③ 「Web アプリとして開く」がオンのまま「追加」
- 追加したアイコンから開き直すこと、開き直したらもう一度ログインが要る場合があることを書く。
- 共有ボタンの位置は iOS の版と配置の設定で変わる。位置を言い切らず、「…」と共有ボタンの両方を絵で見せる。

### P-03 通知を始める

- 追加したアプリで初めて開いたとき 1 回だけ出す。設定からも来られる。
- 「新着メールをこの端末に通知しますか」。プリセットを 3 つから選ぶ:
  - **すべて**: 割り当てられたメールボックスの新着をすべて
  - **重要なものだけ**: To に自分のメールボックスが入っているものと、自分たちが送った会話への返信だけ
    （全メールボックスを「To に入っているときだけ」にし、返信のルールを 1 つ作る）
  - **あとで決める**
- 「通知を許可する」を押した直後に OS の許可ダイアログを出す。**先に OS のダイアログを出さない**。
- 端末名は機種から推測して埋める（「iPhone」「Android」「Mac の Chrome」）。後で変えられる。

### P-04 通知がブロックされている

- OS 側で拒否されたときの画面。アプリからは許可し直せないので、OS の設定の場所を案内する。
  iOS: 設定 → 通知 → Tsubame / Android: 長押し → アプリ情報 → 通知。
- 「許可したら、ここに戻って確かめる」ボタン（`Notification.permission` を読み直す）。

## 5. 通知設定

### N-01 通知設定（トップ）

上から:

1. **この端末の状態**: 「この端末（iPhone）に通知しています」/「この端末は未登録」/「ブロック中」。
   未登録なら「この端末で受け取る」ボタン。
2. **全体スイッチ**「通知」。オフにすると 2 以下を薄くする（値は保つ）。
3. **一時停止**: 1 時間 / 明日の朝まで / 指定の日時まで。停止中は「◯時まで停止中」と解除ボタン。
   止めていた間の分は、解除しても通知しない（通知欄で見られる）ことを 1 行で書く。
4. **プリセット**: すべて / 重要なものだけ / カスタム。細かい設定を変えると自動でカスタムになる。
5. 詳細への行（名前の下に今の要約）:
   - メールボックスごと —「7 個中 4 個で通知」
   - 通知ルール —「4 件（うち「必ず通知」2 件）」
   - おやすみ時間 —「平日 22:00〜7:00 は朝にまとめる」
   - 表示とまとめ方 —「差出人と件名 / 同じ会話は 1 件」
   - 端末 —「3 台（1 台は届いていません）」
6. **キャッチオールを通知する**（スイッチ。既定オン）。キャッチオールの受け皿を 1 つでも見られる人にだけ出す。
   下に「宛先が見つからないメールが届いたとき（2 ドメイン）」と、今の対象数を書く。
   オフでも「必ず通知」のルールに一致したものは通知することを 1 行で添える。
7. **送信失敗を通知する**（スイッチ。既定オン）。
8. 通知欄 —「届いたものを見返す・どうして通知された / されなかったか」。

### N-02 メールボックスごと

- 触れるメールボックスの一覧。色の丸・アドレス・表示名・今のレベル。
- 行を押すと N-03。一覧の上に「すべてを同じにする」。
- owner の特権で見えるだけのアドレスは「割り当てなし（オーナーとして見えるだけ）」の見出しの下にまとめる。
  既定はオフ。ただし**キャッチオールの受け皿は既定で「すべての新着」**。行にラベルを付ける。
  N-01 の「キャッチオールを通知する」がオフのときは、受け皿の行のレベルを薄くし「キャッチオールの通知がオフです」と出す
  （スイッチが上位。受け皿ごとのレベルはスイッチがオンのときだけ効く）。

### N-03 メールボックスの詳細

- 通知レベル（1 つ選ぶ）:
  - **すべての新着**
  - **新しい会話だけ**（返信は通知しない。フォロー中の会話は例外）
  - **To に入っているときだけ**（CC・一斉配信を除く）
  - **通知しない**
- スパムの疑いがあるメール: 通知する / しない（既定しない）。
- このメールボックスに効いている通知ルールの一覧（N-05 へ）。

### N-04 通知ルール

- 優先順の一覧。行に名前・条件の要約・動作のラベル（必ず通知 / 通知 / 音なし / 通知しない）・スイッチ。
- ハンドルで並べ替え。上にあるほど先に効くことを一覧の上に 1 行で書く。
- 「ルールを追加」。よく使うひな形: 「この人からは必ず通知」「ニュースレターを通知しない」「件名に"至急"」。

### N-05 ルールの編集

- 名前。
- 条件（すべてに一致）: 差出人を含む / 宛先を含む / 件名を含む / 本文を含む /
  メールボックス（複数選択）/ 添付あり / 自分たちが送った会話への返信 / CC にだけ入っている。
- 動作: 必ず通知（おやすみ時間も） / 通知 / 音なしで通知 / 通知しない。
- **最近のメールで試す**: 直近 50 通に当てて、一致した件数と例 3 通を出す（`dry-run`）。
- 削除は画面の一番下。

### N-06 おやすみ時間

- スイッチ。
- 時間帯を複数持てる。1 つは曜日（チップ）と開始・終了。日をまたげる。
  既定の追加は「平日 22:00〜7:00」。
- おやすみ中の新着: **通知しない** / **終わったときにまとめて 1 通**（「おやすみ中に 12 件の新着」）。
- 「必ず通知」のルールはおやすみ中も通ることを 1 行で書き、ルール画面へのリンクを置く。
- タイムゾーン（既定は端末の設定）。

### N-07 表示とまとめ方

- **ロック画面の表示**: 差出人・件名・冒頭 / 差出人と件名 / 最小限。選ぶと下の見本が変わる。
- **バッジ**: 全メールボックスの未読 / 通知するメールボックスの未読 / 出さない。
- **同じ会話は 1 件にまとめる**（スイッチ。既定オン）。
- **続けて届いたらまとめる**: まとめない / 1 分 / 5 分 / 15 分。まとめると「新着 5 件」の 1 通になる。
- **他の端末で Tsubame を開いている間は送らない**（スイッチ。既定オフ）。
- できないことを約束しない。次を注記する: iPhone では「音なし」と通知のボタンが効かない /
  Android のバッジは数字でなく点 / 集中モード中は「必ず通知」も OS の設定に従う。

### N-08 端末

- 端末の一覧。名前・種類・最後に届いた日時・「この端末」の印。
- 端末ごと: 受け取る（スイッチ）/ 受け取るメールボックス（すべて / 選ぶ）/ テスト通知 / 削除。
- 失敗が続いている端末は「届いていません（最後の成功: 3 日前）」と出す。
- 一覧の下に「90 日開かれていない端末は自動で削除されます」。

### N-09 通知欄

受信箱のベルと、通知設定の最下段から開く。役割は 2 つ: **届いたものを見返す**、**なぜ通知された / されなかったかを確かめる**。

- 既定の表示は「通知の対象になったもの」だけ（通知したもの + 一時停止・おやすみで止めたもの）。
  スイッチ「対象外も表示」をオンにすると、メールボックスのレベルやルールで外れたものも理由つきで出る。
- 並びは新しい順。最後に通知欄を開いたあとのものには、左に青い点を付ける。開いたら未確認数は 0 に戻る。
- **一時停止中・おやすみ中に止めた分は束にする**。見出しは「一時停止中に届いた 8 件（13:00〜14:00）」。
  束の中は最初の 3 件を出し、「ほか 5 件を表示」で開く。止めた分は解除後も通知しない。
- 1 件ごとに差出人・件名・メールボックス・時刻と、判定の理由を小さく出す。行を押すと会話を開き、
  理由を押すとその設定の画面を開く。理由の文言は理由コードから決める。例:
  - `mailbox_level` →「開発は通知しない設定です」
  - `rule:<id>` →「ルール『ニュースレター』に一致しました」
  - `quiet_digest` →「おやすみ時間のため 7:00 にまとめて通知しました」
  - `paused` →「一時停止中でした」
  - `thread_muted` →「この会話は通知しない設定です」
  - `catch_all_off` →「キャッチオールを通知しない設定です」
- 30 日より前のものは残らない。

## 6. 文言の決まり

- 「通知」「通知しない」で統一する。「プッシュ」は P-01 の説明文でだけ使う。
- 「メールボックス」で統一する（「アドレス」は管理画面の言葉）。
- 時刻は 24 時間表記。「朝」は 7:00 のように必ず時刻を添える。
