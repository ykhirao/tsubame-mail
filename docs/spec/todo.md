# これからやること

**次に何をするかは、この 1 枚だけを見れば分かる。** 残っている作業はここに集める。

分類は 3 つ。**「1. 実装する」だけが手を動かす対象**で、2 と 3 は「やらないと決めたこと」の
置き場所（消すと同じ議論をまた一からやる羽目になるので残す）。

| 分類 | 意味 | 今 |
| --- | --- | --- |
| 1. 実装する | コードを変えれば終わる | 2 件 |
| 2. 実機でしか確かめられない | 走らせないと分からない。コードの変更は伴わないことが多い | 5 件 |
| 3. やらないと決めたもの | 受け入れた制約・運用で守るもの・非目標 | [精査の残件](security-audit.md) §3 ほか |

- ID は `B-n`。B-1〜B-34 のうち B-1〜B-32 は 2026-09-12 に片付けた（中身はその時のコミット）。**次に振る番号は B-35。**
- 優先度は 高（放置すると壊れる・利用者が操作できない）/ 中（要件・画面設計との差、利用者の要望）/ 低（改善）。
- 規模は S（半日）/ M（1〜2 日）/ L（それ以上）。
- 「共有」は `.agents/skills/workstream/SKILL.md` の編集禁止ファイルに手を入れるか。
- **コードを読んで確かめたものだけ**を載せる。読んで疑っただけのものは、確かめてから足す。
- 実環境の値は書かない。

## 2. 実機でしか確かめられない

走らせないと分からないもの。**直す作業ではなく、確かめる作業**。
確かめた結果は [精査の残件](security-audit.md) §3 に移すか、成立したら上の「1. 実装する」に B-n として起こす。

| 何を確かめるか | なぜ確かめられていないか | 出典 |
| --- | --- | --- |
| Cloudflare の `Authentication-Results` が欠けるのはどんなメールか（#127） | Gmail 側に自動転送の設定が要る。公開されている報告は workerd の issue #6740 だけで、Cloudflare からの回答は無い。欠けても未認証扱いになり安全側に倒れる | security-audit §5 |
| 本番の Workers Logs に drizzle のクエリ失敗がどう残るか（#146） | `redactError` を通すようにしたが、実機のログの形を見ていない | security-audit §5 |
| `LOGIN_RATE_LIMIT` / `SEND_RATE_LIMIT` の実機の数え方（#106） | Rate Limiting binding は分散カウントの概算で、厳密な上限ではない | security-audit §5 |
| `X-CF-SpamH-Score` が 5 以上になるメールがあるか（#128 / #140） | 露骨な見本は Email Sending が送信時に拒否するので、外から届くメールで観測できていない。実運用で値が集まったら `parse.ts` `spamVerdictFromScore` を見直す | security-audit §3「受信」 |
| push サービスのどの 4xx を恒久的な失敗とみなすか（#131） | 実挙動を見ていない。今は 4xx が 3 回続いた端末を無効にしている | security-audit §3「プッシュ通知」 |

**検証で本番の送信ドメインを使わない。** スパムの見本や存在しない宛先に送ると
送信ドメインの評判（Bounce rate / Spam rejection rate）が落ち、Cloudflare が送信を止めうる
（security-audit §3「送信」）。
